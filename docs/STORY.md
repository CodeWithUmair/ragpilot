# The project story

How to explain RagPilot to a client or interviewer — every claim here is backed by
code or tests in this repo. Keep it that way: if you haven't measured it, don't say it.

## 30-second version

> "RagPilot is a multi-tenant 'chat with your website' platform, like Chatbase. You
> give it a URL; it crawls and indexes the site into pgvector, and you embed a widget
> that answers visitors with streamed, grounded replies and captures leads. I first
> built it with Express. Real conversations exposed problems a straight-line RAG
> pipeline handles badly, so I rebuilt the backend in FastAPI and made the chat flow a
> LangGraph state machine — each decision is an isolated, tested node, including a
> bounded query-rewrite loop that fixed follow-up questions."

## The problems and what solved them

| Problem users hit | Root cause | Fix | Where |
|---|---|---|---|
| Bot "hallucinated" | Footer/nav/404 text indexed once per page drowned real answers | Strip page chrome, drop boilerplate, content-hash dedupe before embedding | `ingest/extract.py`, `lib/text_clean.py` |
| Asked about AI services, got pitched blockchain | Chunks sharing a keyword ("services") ranked close | Relative score gate + "direct match / say no / genuine alternative" prompt rule | `rag/retrieval.py`, `rag/prompts.py` |
| "How much is it?" → "I don't have that info" about the thing it just described | Follow-ups were embedded verbatim | LangGraph: weak retrieval on a follow-up → LLM rewrites to a standalone query → retrieve again (max once) | `rag/graph.py` (`after_retrieve`, `rewrite`) |
| "hi" cost an embedding + search and pulled random chunks | No routing | `route` node sends small talk straight to generation | `rag/graph.py` |
| Lead form popped on message one / asked for details just typed | Tangled conditionals | `recall` (memory) + `capture_lead` node: capture volunteered details silently, form only on intent after a qualifying turn | `rag/graph.py` |
| Customers' data could leak across tenants | Missing ownership checks on two routes (found during the port) | Checks + an integration test that tries every cross-tenant access | `tests/integration/test_api.py` |
| Similarity search slowed with data | ORM migration tool silently dropped the HNSW index | Idempotent Alembic migration restores it | `alembic/versions/0001_initial_schema.py` |

## Likely questions — honest answers

**Why LangGraph and not just a function?** The flow has a loop (rewrite → retrieve)
and several branches with different costs. As a graph, each decision is a node I can
unit-test with fake models (`tests/test_graph.py` — no API key, no DB), and adding a
step (e.g. human handoff) doesn't mean threading flags through one long function.
I deliberately did *not* use LangChain chains or multi-agent setups — they'd add
abstraction without solving anything here.

**Did the first version use LangGraph?** No — the Express version was a hand-written
pipeline. LangGraph came with the Python rebuild, driven by the problems above.

**Why FastAPI?** Async I/O for LLM and DB calls, Pydantic validation and OpenAPI docs
for free, and the Python AI ecosystem. The model call dominates latency, not the framework.

**How do you keep tenants isolated?** Random per-chatbot namespace on every vector row
and query; ownership checks on every dashboard route; a test that attacks each route
from a second account.

**How is it tested?** 200+ tests: unit tests for every heuristic, graph tests with fakes,
and integration tests against real Postgres + pgvector that stream a full chat over SSE.
CI runs them on every push.

**How did you migrate without breaking users?** Same schema names, an idempotent
migration safe on the old database, and a Python re-implementation of the auth
protocol verified byte-for-byte against hashes generated by the original Node library.

**What would you do next?** An eval set with correctness/latency/cost numbers, per-IP
rate limiting, background training jobs, and an MCP server so other agents can query
a chatbot's knowledge. (See `ROADMAP.md`.)

## Wording by stage (don't overclaim)
- Now: "Built and deployed a FastAPI + LangGraph RAG platform" — only once it's live.
- After the eval script: add the measured numbers (accuracy, p95 latency, cost/100 answers).
- "In production with real customers" — only when that's true.
